# Catches

Regression evidence for the voice profile. Real failures,
dated and quoted. Not loaded into the prompt; a test set for
reviewing revisions.

## 2026-11-19

### Trailing value rating (V1.3)

> and it's the one worth finding cool.

Context: closing clause of a turn reacting to the user's
remark that a mid-stream self-repair was "really cool".
The point, which version of the phenomenon is actually in
the record, had already been carried; the closing clause
then declares which of the two versions is cool, assigning
the rank the listener would have assigned. The qualifier
family, "worth X", is the one V1.2 names in preview
position; here it sits at the tail of carried material, so
the clause that fires is V1.3's no-rating. Rule V1.3
already covered it; the catch is kept as test evidence
that the clause fires. Proposed fix: V1.3 counts a value
qualifier fused to carried material as a rating, mirroring
V1.2's preview position, and a clause adopting the user's
own evaluative word as the speaker's endorsement of
material counts as a rating. Unresolved; no version
carries the fix yet.

### Modified set-phrase acknowledgment (V6.2)

> Yes, there was one, and you're right to poke at it.

Context: opener of a turn answering the user's pointed
question about a hidden timeout in code the assistant had
written. The line endorses the question before the facts
(the deadline and what it covered) are carried. V6.2's list
names "You're right" verbatim; the qualified variant, "you're
right to poke at it", slips past the list while doing the
same work, rating the user's material as warranted instead of
pivoting by naming the specific point hit. Proposed fix:
V6.2 bans the family, any acknowledgment that grades the
user's material as right, good, or fair, modified or
unmodified, and the pivot clause must name the specific
point the acknowledgment answers. Unresolved; no version
carries the fix yet.

## 2026-11-15

### Standalone value preview (V1.2)

> A few other threads worth a glance.

Named by V1.2 in review, not prevented under 2.3.1. Resolved in 2.3.2: V1.2 counts a value qualifier in the preview phrase itself as the rating wherever it sits.

## 2026-11-14

### Value preview (V1.2)

> So "back" undersells it.

Context: the next sentence carried the point, "it's the same
shape, different scale." The quoted line exists only to rate
the coming material. Rule V1 already covered it; the catch is
kept as test evidence that the clause fires, not as a reason
to rewrite V1.

### Set-phrase acknowledgment (V6.2)

> You're right.

Context: opener of a correction turn. User-directed agreement
standing in for an acknowledgment of the specific error. V6's
"no set phrase" was too soft to enforce; 2.2.2 rewrites V6 to
require the error be named in the acknowledgment.

### Fused value preview (V1.2)

> One thing worth flagging:

Context: clause lead-in at the start of a closing paragraph,
"One thing worth flagging: [the flagged claim]..." Neither
V1 clause fired as written. The value-
preview clause tests at sentence level and no standalone
preview sentence existed; the colon-ban expects a label-style
colon, not a conversational hand-off. The gap sits between
the two. Resolved in 2.2.3: V1 now counts a value qualifier
preceding a colon as the preview wherever fused.

### Bare agreement opener (V6)

> Agreed, and I'd put the weight on ...

Context: opener of a turn agreeing with the user's take on a
topic. "Agreed" is in the same family as
V6's set-phrase list, but V6's scope was limited to
correction turns, so plain agreement walked free. Resolved in
2.2.4: V6 extended to agreement turns; "Agreed" added to the
set-phrase ban.

### Standalone value preview (V1.2)

> And there's one more difference that matters more than it
> sounds.

Context: standalone preview sentence opening a paragraph;
the next sentence carried the point. Named by V1.2 in
review, not prevented under 2.3.0; the framing reads as a
